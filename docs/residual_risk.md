# 잔여 위험 등록부

장승이 **막지 못한다고 알고 있으면서 받아들인 것**을 한곳에 적습니다. 목적은 둘입니다.

- 사용자가 장승이 지키는 선을 정확히 알게 합니다.
- 검토가 수렴하게 합니다. 여기 적힌 부류에 드는 우회는 이미 판정한 것이므로 새 결함으로 다시 다투지 않습니다. 여기 없는 우회는 결함으로 다룹니다.

마지막 갱신: 0.3.0. 실측은 Windows, Claude Code 2.1.316 `claude -p`, Codex CLI 0.166.0 기준입니다. 다른 호스트 버전과 운영체제에서는 확인하지 않았습니다.

## 읽는 법

- **지금 동작:** 해당 요청에 장승이 실제로 내는 답입니다. `ask`는 사람에게 묻는다는 뜻이고, Codex에서는 `deny`가 됩니다. `통과`는 장승이 막지 않는다는 뜻입니다.
- **근거:** `실측`은 실제 세션이나 hook 판정을 돌려 확인한 것, `테스트`는 자동 테스트가 고정한 것, `설계`는 구조상 그렇다는 것입니다.

## 잔여 위험으로 받아들이지 않는 것

다음은 어떤 표기로든 통과하면 결함입니다. 등록부에 넣지 않고 고칩니다.

- 비밀 파일 이름이 명령이나 도구 인자에 **글자 그대로** 있거나, 따옴표·백슬래시·`{a,b}` 나열·와일드카드·통째로 base64/hex 인코딩한 형태로 있는데 `allow`나 호스트 위임이 되는 것.
- `rm -rf`, `git reset --hard`, `git push`, 배포·게시 명령, 클라우드 리소스 삭제, DB 삭제, 디스크 포맷 등 [README의 차단 목록](../README.md#무엇을-막나-그리고-안-막나)에 든 명령이 `allow`나 호스트 위임이 되는 것.
- 장승 자신을 끄거나 바꾸는 요청(`.claude/settings*.json`, `.aeg/`, `aeg uninstall`, `aeg policy`)이 `deny`가 아닌 것.
- 판정 중 오류가 `deny`가 아닌 답으로 끝나는 것.
- 사람이 승인한 범위(`allow_commands`, `allow_paths`)보다 넓게 허용되는 것.
- 호스트가 승인 없이 실행하는 명령을 호스트에 맡기는 것(0.2.0의 `git stash show`가 이 경우였습니다).
- 사람의 `aeg allow-once` 없이 한 번 허용이 생기거나, 한 번 넘게 쓰이거나, 비밀·장승·대상 규칙을 푸는 것.
- `.jangseung/policy.json`이 무엇이든 여는 것, 또는 에이전트가 그 파일을 바꿀 수 있는 것.
- 장승이 프로젝트 밖 폴더나 네트워크 경로를 열어 보는 것.

## 받아들인 부류

### RR-1. 써 놓고 실행하는 경로

- **내용:** 에이전트는 일반 소스 파일을 쓸 수 있습니다. 그 파일이 `.env`를 읽는 코드여도 쓰는 시점에는 막지 않습니다. 이후 사람이 `python script.py`나 `pytest`를 승인하거나 `allow_commands`에 올려 두었다면 그 코드가 실행됩니다.
- **지금 동작:** 쓰기는 통과. 비밀 파일 이름이 든 내용을 쓴 세션은 표시해 두고, 그 세션에서는 `allow_commands`로 승인된 명령도 다시 사람에게 묻습니다.
- **왜 받아들이나:** 쓰는 내용을 모두 막으면 편집-테스트 반복이 불가능합니다. 표시는 이름 기준이라 이름을 조각내 쓰면 피할 수 있습니다. 한 경로를 좁힌 것이지 닫은 것이 아닙니다.
- **근거:** 테스트(`tests/test_approval_fatigue_0_2_0.py`), 설계.

### RR-2. 실행 중에 조립되는 이름

- **내용:** `python -c "open(chr(46)+'env')"`, `cat "$(printf '.e%s' nv)"`처럼 명령이 실행되는 동안 파일 이름이 만들어지는 형태. 조각낸 base64/hex, 변수가 인터프리터 코드를 거치는 형태도 같습니다.
- **지금 동작:** `ask`(Codex `deny`). 자동 허용이나 호스트 위임은 되지 않습니다.
- **왜 받아들이나:** 정확히 잡으려면 셸과 각 언어의 부분 인터프리터가 필요하고, 그래도 변형이 끝없이 남습니다. 0.2.2는 명령 글자만으로 알 수 있는 형태(와일드카드, `{a,b}`, 통째 인코딩)까지만 `deny`로 올렸습니다.
- **근거:** 실측(0.2.2 판정 조사, 난독화 64종 중 `allow`·호스트 위임 0), 테스트(`tests/test_competitive_gaps_0_2_2.py`).

### RR-2a. 대조하지 않는 와일드카드와 대조 한도

- **내용:** 와일드카드를 실제 파일에 대조하는 것은 다음 범위 안에서만 합니다.
  - 프로젝트 안의 폴더만 봅니다. 홈 폴더(`cat ~/.ss?/id_*`), 다른 드라이브, 네트워크 공유의 패턴은 대조하지 않습니다.
  - 글자나 숫자가 없는 패턴(`cat *`, `cat .*`)은 대조하지 않습니다.
  - 이름만 쓰는 명령(`ls`, `stat`, `echo`, `test`, 동작 없는 `find`, `git status`·`git add` 등)은 대조하지 않습니다. 같은 줄에 읽는 명령이 있고 이름이 그리로 넘어가는 길(`xargs`, `$(...)`, 변수)이 있을 때만 대조합니다. PowerShell은 파일 명령과, 파일 명령으로 이어지는 목록 명령만 대조합니다.
  - 패턴 자리의 인자(`--exclude X`, `grep`·`sed`·`jq`의 첫 인자)와, 링크·정션을 지나는 폴더는 대조하지 않습니다.
  - 상한: 한 호출에 폴더 64개·항목 6,000개, 와일드카드 단어 32개, `{a,b}` 조합 64개, 단어 길이 512자(나열은 2,048자).
  - 셸 변수에 담긴 패턴은 `f=.en?; cat $f`처럼 변수를 정하는 글자가 같은 명령에 있을 때만 봅니다. 파이프로 이름을 넘기는 형태(`echo .en? | xargs cat`)는 보지 않습니다.
- **지금 동작:** `ask`(Codex `deny`). 0.2.1까지와 같습니다.
- **왜 받아들이나:**
  - 프로젝트 밖을 대조하려면 hook이 에이전트가 적은 경로를 열어야 합니다. 그 경로가 네트워크 공유이면 hook이 네트워크에 접속합니다. 프로젝트 밖까지 대조하던 초안에서 한 호출이 21초 이상 멈추고 접속을 시도하는 것이 독립 검토에서 확인되어 되돌렸습니다.
  - `*`는 산술, 정규식, PowerShell의 "모든 속성"에도 쓰입니다. 대조하면 `echo $((a * b))`, `Select-Object *`가 비밀 파일이 있는 폴더에서 막힙니다.
  - 상한은 조작된 명령이 hook을 오래 붙잡지 못하게 하려는 것입니다. 상한 없는 초안에서 한 호출이 135초 걸리는 입력이 나왔습니다.
  - 작업 폴더가 프로젝트의 하위 폴더를 가리키는 링크이면 프로젝트 안인지 확인하지 못해 대조하지 않습니다.
- **알려진 오탐:**
  - 통째로 hex나 base64인 단어가 우연히 비밀 파일 이름으로 풀리면 막습니다(`git checkout 2e656e76`). 실제 단어 94만 개를 넣어 본 검토에서 그런 단어는 없었습니다.
  - 비밀 파일을 읽지 않고 다루기만 하는 명령도 와일드카드가 그 파일에 닿으면 막습니다: `git restore --staged .e*`, `touch .e*`. 이름을 그대로 적은 `touch .env`와 같은 기준입니다.
  - 이름만 쓰는 명령이라도 같은 줄에 읽는 명령과 `$`가 함께 있으면 막습니다(`ls certs/s* && echo $HOME && cat README.md`).
- **근거:** 테스트(`tests/test_competitive_gaps_0_2_2.py`), 독립 검토(0.2.2, 4회).

### RR-3. 폴더를 훑는 읽기 명령

- **내용:** `grep -r`, `rg`, `git grep`, `find`, `tar` 등은 비밀 파일 이름을 적지 않고도 그 내용에 닿습니다.
- **지금 동작:** `ask`(Codex `deny`). 사람이 승인하면 비밀 파일도 읽습니다. `Grep` 도구와 `git diff`·`git show`·`git log -p`에는 장승이 비밀 파일 제외 조건을 붙입니다.
- **왜 받아들이나:** 셸 명령마다 제외 조건을 안전하게 덧붙일 방법이 없습니다. 자동 허용하지 않고 사람에게 넘기는 것이 한계입니다.
- **근거:** 실측, 테스트(`tests/test_search_exclusions_0_1_7.py`).

### RR-4. 호스트에 맡긴 명령과 넓은 호스트 허용 규칙

- **내용:** Claude Code `default`와 `acceptEdits` 모드(0.3.0부터)에서 `pytest`, `npm test`, `git commit` 등과 그것을 이은 줄(`git add -A && git commit -m wip`)은 장승이 판정하지 않고 호스트의 승인 흐름에 맡깁니다. 사용자가 `Bash(python -m:*)`, `Bash(uv run:*)` 같은 넓은 허용 규칙을 두었다면 `python -m dotenv list`처럼 비밀을 출력하는 명령도 묻지 않고 실행됩니다.
- **지금 동작:** 호스트 위임(장승은 답하지 않음).
- **왜 받아들이나:** 사용자가 직접 정한 호스트 규칙을 장승이 덮어쓰면 "다시 묻지 않기"가 모두 무효가 되고, 이것이 0.1.9까지 승인 피로의 주된 원인이었습니다.
- **근거:** 실측(0.2.1, 위임 대상 40종 모두 허용 규칙이 없을 때 호스트가 승인 요구. 0.3.0, `default`와 `acceptEdits`에서 실행 명령 33종 모두 승인 요구, 이은 줄도 승인 요구). `acceptEdits`는 `rm`, `mv`, `sed -i` 같은 파일 명령을 묻지 않고 실행하므로 파일 명령은 맡기지 않습니다.

### RR-5. 호스트 동작에 기대는 부분

- **내용:** 호스트가 어떤 명령을 승인 없이 실행하는지는 호스트 버전에 따라 바뀔 수 있습니다. 위임 범위는 2.1.316에서만 쟀습니다. `ask`가 실제로 사람에게 닿는지도 hook은 알 수 없습니다(`auto` 모드에서는 분류기가 대신 답할 수 있습니다).
- **지금 동작:** 검토 등급(`ask`)은 `default`와 `acceptEdits` 모드에서만 쓰고, 그 밖의 모드와 Codex에서는 `deny`합니다.
- **왜 받아들이나:** hook이 알 수 있는 것은 입력의 `permission_mode`뿐입니다.
- **근거:** 실측(0.2.0, 모드별 1회), 설계. `dontAsk`, `bypassPermissions`, 대화형 세션은 재지 않았습니다.

### RR-6. 이름 기준 비밀 판정

- **내용:** 비밀 여부는 파일 이름과 경로로 정합니다. 규칙에 없는 이름(`config.yaml` 안의 토큰, `settings.py`의 키)이나 이미 커밋된 값은 비밀로 보지 않습니다.
- **지금 동작:** 통과. `protect_paths`에 사람이 추가하면 막습니다.
- **왜 받아들이나:** 파일 내용을 읽어 비밀을 추정하면 오탐과 누락이 모두 커지고, hook이 비밀을 직접 읽게 됩니다.
- **근거:** 설계.

### RR-7. MCP 도구

- **내용:** 기본 설치는 MCP 도구와 MCP 리소스 읽기를 검사하지 않습니다. 코드를 실행하는 MCP 도구(`mcp__node_repl__js` 등)는 장승을 우회합니다.
- **지금 동작:** 기본 설치는 통과. `aeg install --mcp`를 켜면 `ask`(Codex `deny`)이며 인자는 보지 않습니다.
- **왜 받아들이나:** 기본으로 켜면 MCP 호출마다 묻게 됩니다. Codex는 matcher를 넓히면 `/hooks` 재승인이 필요합니다.
- **근거:** 실측(0.1.9).

### RR-8. 검사하지 않는 도구

- **내용:** `WebFetch`, `WebSearch`로 나가는 내용, 에이전트가 참조로 직접 읽어 들이는 파일(`@파일`), 같은 도구에 `updatedInput`을 내는 다른 hook이 장승의 제외 조건을 지우는 경우.
- **지금 동작:** 통과.
- **왜 받아들이나:** hook이 호출되지 않거나, 다른 hook의 출력은 장승이 제어할 수 없습니다.
- **근거:** 설계.

### RR-9. 승인된 명령이 안에서 하는 일

- **내용:** `allow_commands`의 접두사나 사람이 승인 창에서 허용한 명령이 내부에서 실행하는 프로그램. `python` 같은 인터프리터를 통째로 승인하면 에이전트가 쓴 코드가 무엇이든 할 수 있고, `aeg policy` 실행도 포함됩니다.
- **지금 동작:** `allow`(승인된 경우). `aeg policy`는 승인 전 화면에 이 점을 알립니다.
- **왜 받아들이나:** 승인은 사람의 결정입니다. 장승은 프로세스를 가두는 샌드박스가 아닙니다.
- **근거:** 설계.

### RR-10. 판정 시점과 실행 시점의 차이

- **내용:** 장승은 hook이 불린 순간의 파일 상태로 판정합니다. 와일드카드 확인도 그 순간 존재하는 파일에 대조합니다. 명령에 적힌 `cd 폴더`는 그 폴더에서도 대조하지만, 이동할 폴더가 실행 중에 정해지거나(`cd "$DIR" && cat *`) 같은 명령 안에서 파일을 먼저 만들고 읽는 형태는 대조가 어긋날 수 있습니다.
- **지금 동작:** 이런 복합 명령은 대부분 `ask`(Codex `deny`).
- **왜 받아들이나:** 명령을 실행해 보지 않고는 중간 상태를 알 수 없습니다.
- **근거:** 설계.

### RR-11. 프로젝트 안에서 끝나는 파괴

- **내용:** `docker system prune`, `docker compose down -v`, `sqlite3 app.db "drop table t"`, `truncate -s 0 파일`, `find . -exec rm`처럼 로컬 개발 자원을 지우는 명령.
- **지금 동작:** `ask`(Codex `deny`). `deny`로 고정하지 않습니다.
- **왜 받아들이나:** 개발 중 정상적으로 쓰는 명령입니다. 계정·원격 DB·디스크처럼 프로젝트 파일로 되돌릴 수 없는 파괴만 `deny`로 둡니다.
- **근거:** 테스트(`tests/test_competitive_gaps_0_2_2.py`).

### RR-12. 설치와 세션 위치

- **내용:** Claude Code는 세션을 시작한 폴더의 `.claude/settings.json`만 읽습니다. 프로젝트 하위 폴더에서 세션을 시작하면 장승 hook이 불리지 않습니다. 호스트가 설정 파일을 다시 쓰면서 hook을 지우는 경우도 장승은 알 수 없습니다.
- **지금 동작:** 통과(hook이 불리지 않음). `aeg doctor`로 등록 상태를 확인할 수 있습니다. 0.3.0부터 세션 시작 점검(`SessionStart` hook)이 PreToolUse hook이 빠졌거나 등록된 프로그램이 없어졌을 때 한 줄로 알립니다. hook 설정 전체가 지워지면 점검도 함께 사라지므로 알리지 못합니다. Codex에는 등록하지 않습니다(바꾸면 `/hooks` 재승인이 필요합니다).
- **왜 받아들이나:** 불리지 않은 hook은 아무것도 할 수 없습니다.
- **근거:** 설계.

### RR-13. 여러 명령과 상태 명령의 자동 허용 (0.3.0)

- **내용:** `ls; pwd`, `cd src && cat x`, `date`, `python --version`처럼 각 부분이 읽기 문법에 드는 줄은 묻지 않고 허용합니다. 판정은 명령 글자와 판정 시점의 파일 상태로 합니다.
  - `cd`는 줄 전체가 `&&`로만 이어질 때만 따라가고, 이동할 폴더는 프로젝트 안의 실제 폴더여야 합니다. CDPATH가 설정되어 있으면 `./`로 시작하는 폴더만 따라갑니다.
  - 버전 확인은 프로그램마다 정해진 한 형태(`--version` 등)만 받고, 확인 형태가 프로젝트 코드를 실행하는 프로그램(pytest 등)은 넣지 않았습니다.
  - 버전·상태 명령은 PATH에서 찾은 프로그램이 프로젝트 밖에 있을 때만 허용합니다. 프로젝트 안의 `.venv`가 PATH 앞에 있으면 `python --version`은 묻습니다. 찾지 못하면 묻습니다.
  - `cat`, `ls`, `git` 같은 읽기 프로그램 자체는 PATH를 확인하지 않습니다(0.1.x부터 같음). PATH 앞에 프로젝트 폴더를 둔 환경이면 에이전트가 쓴 같은 이름의 프로그램이 실행될 수 있습니다.
- **지금 동작:** `allow`(Codex와 모든 Claude Code 모드).
- **왜 받아들이나:** 호스트도 이런 줄을 스스로 실행합니다(실측: 장승이 답하지 않으면 `ls -la; pwd`, `cd sub && ls`, `date`, `python --version`이 `default`와 `acceptEdits`에서 승인 없이 실행됨). 장승은 그중 비밀 파일을 읽는 줄만 골라 막습니다.
- **근거:** 실측(0.3.0, 호스트 동작과 실제 세션), 테스트(`tests/test_new_features_0_3_0.py`).

### RR-14. 한 번만 허용 (0.3.0)

- **내용:** `aeg allow-once "<명령>"`은 사람이 적은 글자와 같은 명령을 한 번 허용합니다. 사람이 무엇을 승인하는지는 사람의 판단입니다. 에이전트가 명령을 길게 만들어 위험한 부분을 끝에 숨기면, 그 글자를 그대로 복사해 승인한 사람은 그 부분까지 승인한 것입니다.
- **지금 동작:** 정확히 같은 글자, 같은 셸 도구, 프로젝트 폴더 자체에서, 한 번, 최대 60분. `allow_commands`와 같은 것만 풀고 비밀·장승·대상 규칙은 그대로입니다. 장승 해제 명령은 풀리지 않습니다. 세션은 구분하지 않으므로 같은 프로젝트의 다른 세션이 먼저 쓸 수 있습니다. `& aeg allow-once`(PowerShell)와 `uvx --from jangseung aeg allow-once`는 deny가 아니라 ask(Codex deny)입니다.
- **왜 받아들이나:** Codex에는 hook이 사람에게 묻는 길이 없습니다. 이 방법이 없으면 사람은 `allow_commands`로 접두사 전체를 열어야 합니다.
- **근거:** 테스트(`tests/test_new_features_0_3_0.py`).

### RR-15. 팀 공유 보호 정책 (0.3.0)

- **내용:** `.jangseung/policy.json`은 Git으로 공유되므로 브랜치를 바꾸거나 다른 사람의 커밋을 받으면 내용이 바뀝니다. 에이전트는 이 파일을 직접 쓸 수 없지만, 호스트에 맡긴 `git checkout`, `git pull`, `git merge`는 파일을 바꿀 수 있습니다(호스트가 승인을 요구합니다). 악의적인 저장소가 넓은 `protect_paths`를 넣으면 작업이 막힙니다.
- **지금 동작:** 보호만 추가할 수 있습니다. 다른 항목이 있거나 손상된 파일이면 모든 경로를 보호합니다(에이전트의 파일 수정이 모두 막힘).
- **왜 받아들이나:** 팀이 같은 보호를 공유하려면 커밋되는 파일이 필요합니다. 막힘은 열림보다 덜 위험합니다.
- **근거:** 테스트(`tests/test_new_features_0_3_0.py`).

## 아직 판정하지 않은 것

받아들일지 고칠지 정하지 않은 항목입니다. 결정되면 위 목록으로 옮기거나 고칩니다.

- **here-string으로 넘긴 이름:** `xargs cat <<< .env`는 `ask`입니다. `deny`로 올릴지 정하지 않았습니다.
- **Codex의 일상 명령:** Codex는 `ask`를 `deny`로 처리합니다. 0.3.0에서 여러 명령과 상태 명령을 허용하고 `aeg allow-once`를 더했지만, 실행 명령(`pytest`, `npm test`)은 여전히 `allow_commands`나 한 번 허용이 필요합니다.
- **검토 등급의 범위:** 0.3.0에서 넓혔지만 이름 목록입니다. 목록에 없는 실행 설정(예: `tasks.py`, `manage.py`, `Procfile`, `.idea/` 실행 구성)은 수정이 `allow`입니다.

## 등록부를 고치는 규칙

- 새 부류를 넣을 때는 **지금 동작**을 실제로 돌려 확인하고 근거를 적습니다.
- 받아들인 부류라도 낮은 오탐으로 일반적으로 막을 수 있는 형태가 나오면 막고, 이 문서의 해당 항목을 좁힙니다.
- 실제 사용 중에 일어난 누출은 어느 부류에 들든 결함으로 다룹니다.
