# 장승 0.3.3 — 0.3.2 개인 승인 저장소의 결함 4건 수정

[English](release_0.3.3.en.md)

0.3.2가 개인 승인을 사용자 프로필로 옮기면서 생긴 결함을 고칩니다. 판정 규칙은 바뀌지 않았습니다.

```bash
python -m pip install --upgrade jangseung==0.3.3
```

플러그인으로 쓰면 플러그인도 업데이트하세요. `aeg install`을 다시 실행할 필요는 없습니다.

## 고친 것

- **호출마다 판정하는 hook이 0.3.2에서 약 13 ms 느려졌습니다.** 프로필 폴더를 찾으려고 호출마다 `ctypes`와 셸 라이브러리를 불러왔기 때문입니다. 이제 Windows가 프로필 폴더를 적어 두는 레지스트리(`HKLM`, 관리자만 고칠 수 있음)에서 읽습니다. 환경 변수는 여전히 믿지 않습니다. 이 프로세스가 열 수 있는 사용자 하이브가 하나가 아니면(관리자 권한 등) 전처럼 셸에 묻습니다.
  - 같은 PC에서 번갈아 160회씩 잰 중앙값: 0.3.1 52.2 ms, 0.3.2 65.5 ms, 0.3.3 54.0 ms. 상주 판정 경로는 0.3.2에서도 영향이 없었습니다(34.5 ms 대 34.7 ms).
- **Python 버전이 다르면 승인을 찾지 못했습니다 (Windows).** 승인을 넣는 폴더 이름에 `st_dev`가 들어가는데, Python 3.12 이상은 64비트 볼륨 일련번호를, 3.11 이하는 그 하위 32비트를 돌려줍니다. `aeg policy add`를 실행한 Python과 hook을 실행하는 Python이 다르거나 Python을 3.12 이상으로 올리면 승인이 적용되지 않았습니다. 이제 모든 버전이 돌려주는 비트만 씁니다.
  - 0.3.2가 Python 3.12 이상에서 만든 폴더는 그대로 읽고, 다음에 승인을 쓸 때 새 이름으로 옮깁니다. 다시 승인할 필요가 없습니다.
- **프로필 폴더를 쓸 수 없으면 모든 파일 수정이 막혔습니다.** 개인 정책이 없는 사용자도 해당됐습니다. 프로필 폴더가 링크나 정션인 경우, 사용자 정보가 없는 컨테이너, 홈 폴더가 그룹 쓰기 가능한 경우입니다. `aeg policy add`도 그런 곳에는 쓰지 않으므로 거기에 사람이 승인한 것이 있을 수 없습니다. 이제 "개인 승인 없음"으로 처리합니다. 기본 규칙, 팀 정책, 체크아웃의 `protect_paths`는 그대로 적용되고, 세션 시작 점검과 `aeg doctor --hooks`가 알려 줍니다.
  - 달라지지 않은 것: 프로젝트가 승인 저장소를 포함하거나 그 안에 있으면 전처럼 모든 경로를 보호합니다. 저장소 안의 폴더나 파일이 링크이거나 손상된 경우도 전과 같습니다.
- **예전 허용 항목이 안내 없이 무시되었습니다.** `.aeg/policy.json`에 남은 `allow_paths`, `allow_commands`, `allow_mcp_tools`는 0.3.2부터 쓰이지 않습니다. 이제 채택하지 않은 항목이 남아 있으면 세션 시작 때 한 줄로 알리고 `aeg doctor --hooks`가 WARN을 냅니다. `aeg policy adopt`로 검토해 채택하거나 그 파일에서 지우면 안내가 사라집니다.

## 확인 결과

- 자동 테스트: Windows, Python 3.14에서 1990 passed, 21 skipped. 새 테스트는 `tests/test_approval_storage_0_3_3.py`입니다.
- 승인 폴더 이름: 같은 프로젝트에서 Python 3.10.20과 3.14.5가 같은 이름을 냈습니다(0.3.2에서는 달랐습니다).
- 프로필 경로: 이 PC에서 레지스트리로 읽은 값과 셸이 돌려준 값이 같았습니다(0.24 ms).
- 0.3.1, 0.3.2, 0.3.3의 답: 명령 4종에서 같았습니다.
- 확인하지 않은 것: 관리자 권한 세션(셸에 묻는 경로로 돌아감), 도메인·Azure AD 계정의 프로필, macOS 실제 세션, 사용자 정보가 없는 실제 컨테이너(테스트에서 흉내만 냄).
